Julia blocks are syntax-highlighted like every other language on this
blog, but pressing **Run** won't execute anything yet:

<CodeRunner client:only="react" lang="julia" code={`function fib(n)
    n <= 1 ? n : fib(n - 1) + fib(n - 2)
end

println(fib(10))
`} />

That's not a bug — it's `UnsupportedRuntime` doing its job. Python runs on
[Pyodide](https://pyodide.org) and R runs on
[webR](https://docs.r-wasm.org/webr/latest/), both mature WebAssembly
builds with a JS API for loading the interpreter and piping code in.
Nothing comparable exists for Julia yet: its JIT-heavy runtime doesn't
compile down to a small, interactive WASM build the way CPython and R's C
core do. Experimental ahead-of-time compilers exist, but none give you a
REPL you can throw arbitrary code at from a browser tab.

So instead of pretending it works, the block above fails loudly with a
clear reason instead of a silent crash — the same treatment Haskell gets.
The moment a real in-browser Julia runtime shows up, wiring it in is one
new file in `src/runtimes/` and a registry entry, same as R was.
